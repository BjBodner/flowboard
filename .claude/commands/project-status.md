# /project-status — סטטוס הפרוייקט

בצע את הפעולות הבאות **לפני** שאתה כותב את הסיכום:

1. קרא את `CLAUDE.md` כדי להבין את ארכיטקטורת הפרוייקט.
2. קרא את כל קבצי `src/` (רקורסיבי) — רכיבים, hooks, types, styles.
3. הרץ `npm run lint 2>&1 | head -60` כדי לגלות שגיאות ואזהרות.
4. הרץ `npm run build 2>&1 | tail -30` כדי לבדוק אם ה-build עובר.
5. חפש TODO / FIXME / HACK בקוד: `grep -rn "TODO\|FIXME\|HACK\|XXX" src/`.
6. בדוק אם יש קבצים ריקים או stubs: `find src/ -empty`.

לאחר שאספת את כל המידע, כתוב את הסיכום בפורמט הבא **בעברית**:

---

## מצב הפרוייקט — FlowBoard

### מה עובד ✅
רשום 3-7 נקודות bullet של תכונות שקיימות בקוד ועובדות (לפי ניתוח הקוד, לא לפי הנחה).

### מה לא עובד / חסר ⚠️
רשום בעיות שמצאת: שגיאות lint, build failures, TODO פתוחים, רכיבים לא גמורים, היגיון שבור, או תכונות שחסרות לחלוטין לפי ארכיטקטורת הפרוייקט. אם לא מצאת בעיות — כתוב "לא נמצאו בעיות ידועות".

### משימות מומלצות לפי עדיפות 📋
רשום 3-5 משימות קונקרטיות שכדאי לבצע עכשיו, ממוינות מחשוב לפחות דחוף. כל משימה: שורה אחת ברורה.

### אנלוגיה מהחיים 🎭
בחר **אנלוגיה אחת** מחיי היומיום (לא מתחום הטכנולוגיה) שממחישה את המצב הנוכחי של הפרוייקט — מה בנוי, מה עדיין פתוח, ולאן הולכים. כתוב אותה כפסקה קצרה של 2-4 משפטים, כמו שהיית מסביר לחבר שאינו מתכנת.
